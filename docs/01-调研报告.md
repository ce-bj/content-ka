本文回答两个问题：
1. **为什么做**：业务背景。
2. **对标什么**：HubSpot 蓝本，以及全球 AI-ready 内容平台厂商的做法。

产品怎么做，见《02-产品 PRD》。

## 一、背景

### 1.1 为什么知识和内容要一起做

海外 B2B 买家的采购方式已经变了：联系供应商之前，大部分研究已经通过搜索引擎、AI 工具、官网和专业内容完成。

| 指标 | 数据 |
|---|---|
| 最近一次采购中使用生成式 AI 收集信息的 B2B 买家 | 45% |
| 联系供应商前已形成短名单的制造业买家 | 81% |
| 把供应商官网作为第一信息源的制造业买家 | 37% |

竞争的关键，因此从“有没有投放、参展”变成了两件事：
- 企业知识能不能被治理成 AI 可用的事实；
- 内容能不能基于这些事实持续生产、统一管理并送达每个渠道。

对全球化企业来说，这是同一个问题：
- 企业知识（规格、参数、认证、案例、交付能力）散在 ERP、文档和人的经验里。不经治理，AI 和内容生产都无事实可用。
- 内容在多品牌、多区域、多语种站点下各自生产，审批缺失，无法统一管理和归因。

> 知识治理的终点是内容，内容统一管理的起点是知识。所以 KDH（企业知识库）与 CMS 必须作为一个整体方案。

### 1.2 目标客户

全球化企业：从成长型客户中出现多品牌、多区域、多站点、多部门采购或系统集成信号的客户转入。

| 客户层级 | 参考标准 | 服务模式 | 成熟期目标 ACV（参考） |
|---|---|---|---|
| 战略级 | 行业龙头 / 灯塔，年营收 50 亿元以上 | 专属 POD + 高管 Sponsor + 定制方案 | 300 万元以上 / 年 |
| 重点级 | 细分行业 Top 10，年营收 10—50 亿元 | POD 共享 + 专属 CSM + 行业方案 | 100—300 万元 / 年 |
| 标准级 | 五维达标、复杂度较低，年营收 5—10 亿元 | 标准企业版 + 轻量 FDE | 20—100 万元 / 年 |

三类客户原型对 CMS 的诉求：

| 原型 | 对 CMS 的核心诉求 |
|---|---|
| A 级专精特新龙头 | 内容团队小，最需要基于知识的 AI 内容生产 |
| S 级行业链主 | 产品规格多、渠道复杂，最需要完整的内容供应链 |
| B 级多品牌集团 | 最需要多品牌的知识与内容分区 |

### 1.3 整体方案：一个核心、两个扩展

| 方案 | 构成 | 客户买到的能力 | 交付方式 |
|---|---|---|---|
| **整体核心** | KDH 企业版 + 内容中心企业版（CMS），不可分割 | 企业知识治理；内容统一管理（AI 生产、审批、多站点分发、个性化、归因） | 一次性完整交付 |
| 扩展一：全球可见性 | 整体核心 + SEO Agent + GEO Agent | 搜索与 AI 答案可见性诊断、内容优化任务、复测 | 合同预留，信号触发 |
| 扩展二：全渠道售前 | 整体核心 + SDR Agent（访客转化 + 商机转化）+ CRM 协同 | 访客接待、资格判定、预约交接 | 合同预留，信号触发 |

**商品口径**：内容中心 = AI 门户 + 社媒运营 Agent + 内容管理。全球化企业的内容中心企业版以内容管理（CMS）为核心，可以不替换客户现有官网（反向代理叠加）。

**两个扩展与 CMS 的关系**：
- SEO / GEO Agent 的优化任务直接作用于 CMS 内容，引用的事实取自 KDH。
- SDR Agent 的答案依据 KDH，对话发生在 CMS 页面上，并做内容推荐。

### 1.4 两条总原则

KA 方案 2.3 节：

- **一条价值链**：知识源 → KDH 治理 → CMS 生产与统一管理 → 全渠道分发 → 效果回流。环环相扣，任一环节缺失，其他环节都不成立。
- **一份事实源**：CMS 的内容只引用 KDH 授权的知识事实，知识更新可以联动内容更新。两个系统在模型、权限、审计上是一套机制。

价值链的六个环节（KA 方案 3.1）：

| 环节 | 承担 | 关键动作 | 输出 |
|---|---|---|---|
| ① 知识盘点 | KDH | 盘点 ERP / PIM / DAM、文档与人员经验，划分知识域 | 知识源清单 |
| ② 知识治理 | KDH | 结构化、证据等级、有效期、分级权限、审核流程 | 可被 AI 与内容引用的知识资产 |
| ③ 内容生产 | 内容中心 | 基于 KDH 授权事实，AI 生产图文 / 页面 / 社媒 / 视频脚本，Brand Voice 统一口径 | 合规内容成稿 |
| ④ 统一管理 | CMS | 多级审批、分区、多站点 / 多语言、Content Remix、发布门禁 | 可发布内容资产 |
| ⑤ 全渠道分发 | CMS | 多站点、多语种、多渠道一次分发，反向代理与现有站点并存 | 渠道触达 |
| ⑥ 监测回流 | KDH + CMS | 效果与访客 / 线索数据回流，归因，反哺知识更新与选题 | 经营看板与下一轮输入 |

**耦合机制**：
- 内容引用的事实只取自 KDH，按权限生效；
- KDH 知识更新可以触发关联内容复核；
- 权限、审计、计量是一套体系。

### 1.5 内容中心企业版的要求

KA 方案 3.3 节：

- 内容中心企业版（CMS）的**蓝本是 HubSpot Content Hub Enterprise**。
- 第二阶段要完整、一次性交付三部分：**六组企业版能力 + 开发者能力 + 内容供应链运行机制**。
- **不做功能分期或“首期版”**。在 KA 项目 13 周内一次部署。
- 标准企业版与共创企业版的区别只在服务与实施深度，不在功能多少。

**内容供应链**（KA 方案 3.3.3）：

| 环节 | 要求 |
|---|---|
| 选题 | 基于 KDH 知识资产、区域市场与买家问题确定主题：AI 建议，内容负责人确认 |
| 生产 | AI 依据 KDH 授权事实起草，Brand Voice 统一口径 |
| 审批 | 多级工作流：业务 / 品牌 / 合规按分区审批，红线人工放行 |
| 发布 | 一次审核，多站点、多语种、多渠道分发；Content Remix 转译；发布门禁校验事实与标识 |
| 复盘 | 效果回流、归因分析，反哺知识更新与选题 |

AI 生成的内容依法标识。对客户承诺流程与过程指标，不承诺排名或流量数字。

### 1.6 KDH 企业版提供什么

内容 CMS 的上游是 KDH 企业版。

| 能力组 | 具体能力 |
|---|---|
| 企业知识库 | 品牌、产品事实、规格参数、案例、资质与交付事实；证据等级、有效期、分级权限；多品牌知识隔离；入库审核流程 |
| 行业知识库 | 行业术语、技术参数标准、买家高频问题；跨客户复用 |
| 统一数据底座 | 身份与受众、数据治理、分析与指标 |
| 知识工程方法 | 盘点、知识域划分、统一事实模型、批量导入 + AI 辅助抽取、专家审核 |

### 1.7 约束条件

| 类别 | 要求 |
|---|---|
| 部署 | 公有云 SaaS、混合部署（CMS 云化，KDH 与敏感数据本地）、全私有化三种形态，**同一代码基线**，不出现私有化专属分支 |
| 信创 | 私有化支持 x86 / ARM，兼容麒麟、统信、达梦、人大金仓；第二阶段不承诺信创全栈认证 |
| 基础设施 | 统一账号、权益计量、API / MCP 网关、Agent 运行与治理由**业务平台基础设施**提供，产品不重复建设 |
| 合规 | AI 内容依法标识；红线动作（价格、折扣、交期、承诺、对外发送、内容下架等）默认人工确认；客户数据用于训练须合同授权 |
| 边界 | 不替换客户现有官网与 CRM（反向代理叠加、CRM 协同写入）；FDE 只做配置集成，不写产品内核 |
| 出口条件（2027 年 6 月末） | 整体核心在 1—2 家样板完整上线：知识治理实际运行，内容统一管理实际运行（AI 生产 → 多级审批 → 多渠道分发）；CMS 企业版完整能力一次部署 |

## 二、调研一：对标 HubSpot Content Hub Enterprise

KA 方案指定 HubSpot Content Hub Enterprise 为蓝本。

**对标原则**：结合我们的定位——CMS 只做“生产与统一管理”，其他环节对接别的平台——蓝本里的每项能力分三种对标方式：

| 对标方式 | 含义 |
|---|---|
| **自建** | CMS 自己做 |
| **自建数据 + 对接运行** | CMS 管内容和数据，页面上的执行由门户或其他平台负责 |
| **对接** | 完全由其他平台负责，CMS 不需要界面 |

### 2.1 ① 可扩展 CMS 与全球站点

| HubSpot 能力 | KA 要求 | 对标方式 | 我们对标的功能 |
|---|---|---|---|
| 多站点 / 多根域名 | 核心域名 + 9 个附加根域名，共 10 个 | 自建数据 + 对接运行 | 站点清单、内容所属站点、语种与页面的对应关系；站点由门户承载 |
| 站点权限隔离 | 多品牌 / 区域站点集中管理 | 自建数据 + 对接运行 | 按站点授权调用方；成员范围可细到站点 |
| 主题、模块跨站共享 | — | 自建数据 + 对接运行 | 内容组件跨类型、跨站复用；主题归门户 |
| 多语言与 hreflang | — | 自建 | 语种版本、翻译、术语库、回退语种、hreflang 输出 |
| 全球 CDN / SSL / 99.99% SLA | — | 对接 | 门户与平台负责 |
| 反向代理 | 与现有网站并存 | 对接 | 门户负责 |

### 2.2 ② 动态内容与结构化数据

| HubSpot 能力 | KA 要求 | 对标方式 | 我们对标的功能 |
|---|---|---|---|
| HubDB 数据表与动态页面 | 产品目录、资源库、门店 / 伙伴名录 | 自建数据 + 对接运行 | 数据表型内容，表格内编辑；绑定事实的列只读并自动刷新；页面由门户按行生成 |
| 自定义 CRM 对象驱动内容 | — | 自建 | 内容模型 + KDH 事实对象（比 CRM 对象多了证据与有效期） |
| 批量导入与 API | — | 自建 | 导入预检（与事实不一致的行报错）+ Management API |
| 内容随数据自动同步 | 海量目录页维护成本趋近于零 | 自建 | 事实插槽自动刷新；正文引用生成复核任务 |

### 2.3 ③ AI 内容生产

| HubSpot 能力 | 对标方式 | 我们对标的功能 |
|---|---|---|
| AI 博客写作 | 自建 | 选题 → 模板生成，只用 KDH 授权事实，生成依据随版本保存 |
| 内容助手（改写 / 翻译 / 调语气） | 自建 | 编辑器 AI 面板；AI 段落有标识，需逐段确认 |
| Brand Voice | 自建 | 语调、禁用词、必用表述、示例；生成时套用，发布时检查 |
| Content Remix 一稿多渠道复用 | 自建 | 一稿多用：源内容须已生效，目标稿继承源事实 |
| AI 视频剪辑 / 字幕 / 多语配音 | 字幕自建，剪辑与配音对接 | 字幕、摘要、关键帧在资产 AI 中完成；剪辑、配音调用外部工具，产出入资产库 |
| 播客工具 | 对接 | 调用外部工具，音频入资产库 |

### 2.4 ④ 内容治理

| HubSpot 能力 | 对标方式 | 我们对标的功能 |
|---|---|---|
| 多级审批工作流 | 自建 | 按范围 × 内容类型匹配审批链，可设条件与时限 |
| 分区管理 | 自建 | 范围模型：品牌 / 事业部 × 区域 × 语种 × 站点 / 渠道 |
| 层级团队权限 | 自建 | 组织层级 + 角色矩阵 + 红线字段 |
| 活动日志 | 自建 | 审计日志，可按事实追溯全链路 |
| SSO | 对接 | 平台统一账号 |
| 发布门禁 | 自建 | 发布检查：证据等级、过期、冲突、可见级别、资产授权、禁用词、AI 未确认 |
| 代码警报 | 对接 | 门户负责 |

### 2.5 ⑤ 体验与个性化

| HubSpot 能力 | 对标方式 | 我们对标的功能 |
|---|---|---|
| Smart Content（按属性 / 生命周期 / 地区 / 来源展示） | 自建数据 + 对接运行 | 内容变体与受众规则；门户在运行时选择 |
| 个性化令牌 | 自建数据 + 对接运行 | 令牌占位与回退文字；门户替换 |
| 会员内容 | 自建数据 + 对接运行 | 访问级别（公开 / 会员 / 经销商）；门户校验 |
| A/B 测试、自适应测试 | 自建数据 + 对接运行 | 变体带实验分组与流量比例，接收各变体效果；门户分流 |

### 2.6 ⑥ 归因与分析

| HubSpot 能力 | 对标方式 | 我们对标的功能 |
|---|---|---|
| 内容归因到联系人 / 商机 / 收入 | 对接（数据底座） | 接收按内容 + 版本的效果与线索回传 |
| 多域统一报表 | 对接（数据底座） | 按调用方 / 站点汇总调用与效果 |
| SEO 建议 | 对接（SEO / GEO Agent） | 输出 JSON-LD 与机器可读摘要；Agent 建议进入审核收件箱 |
| 视频与多渠道分析 | 对接（数据底座） | 按渠道的调用与效果 |

### 2.7 开发者能力

| HubSpot 能力 | KA 要求 | 对标方式 | 我们对标的功能 |
|---|---|---|---|
| 开放 API 与 SDK | 内容、数据表、站点与发布能力的完整 API | 自建 | Delivery / Preview / Management API、MCP、Webhook、SDK |
| 模板语言与主题框架 | 可视化编辑与代码开发双轨 | 对接 | 门户负责 |
| 本地 CLI / CI-CD | 本地开发、版本管理、自动化发布 | 自建 | 开发 / 预发 / 生产环境之间迁移模型与规则；导出给 CLI / CI |
| Serverless Functions | 定制业务逻辑、第三方 API 集成 | 自建 + 对接 | 钩子 + 自动化流程；自定义代码通过 Webhook 调用外部函数 |
| 自定义数据 / 对象 | 支撑复杂内容场景 | 自建 | 运行时内容建模 + 数据表 |
| 企业级托管扩展 | 自定义 CDN、代码警报、性能监控 | 对接 | 门户与平台负责 |

### 2.8 对标小结

| 范围 | 项数 | 自建 | 自建数据 + 对接运行 | 完全对接 |
|---|---|---|---|---|
| 六组能力 | 31 | 14 | 8 | 9 |
| 开发者能力 | 6 | 4 | 0 | 2 |

注：
- 2.1—2.7 每张表各算一行，共 37 项。
- “视频剪辑 / 字幕 / 配音”是部分自建、部分对接，算作自建。
- Serverless 是自建 + 对接，算作自建。

**结论**：
- 蓝本里“生产与管理”类的能力，我们全部自建，并在事实约束上比蓝本更严：
  - 只用授权事实；
  - 发布门禁以事实为主；
  - 事实变更联动复核。
- 蓝本里“站点与运行时”类的能力（域名、CDN、主题、个性化运行、归因计算），我们交给门户与数据底座。CMS 把它们需要的数据（站点、hreflang、变体、实验、令牌、访问级别）准备好并通过接口提供。

## 三、调研二：全球 AI-ready 内容平台厂商（附录 A）

### 3.1 研究范围

研究覆盖 22 家厂商：
- **CMS / DXP**：Adobe、Sitecore、Contentful、Contentstack、Storyblok、Sanity、Acquia、Optimizely、Hygraph、Progress Sitefinity、Kontent.ai
- **DAM**：Bynder、Aprimo、Cloudinary、Brandfolder、Frontify、Orange Logic
- **内容与知识平台**：Box、Microsoft、Salesforce
- **AI 内容平台（作为参照）**：Writer、Jasper

### 3.2 行业方向

2025—2026 年，DAM 与 CMS 厂商的叙事从“人用的内容仓库 / 建站工具”转向“给 AI Agent 供料并设限的内容基础层”。最一致的三条动作：

| 动作 | 代表厂商 |
|---|---|
| 用 MCP Server 重新包装内容 API，让外部 Agent 以与人相同的权限读写内容 | Adobe、Contentful、Contentstack、Storyblok、Cloudinary、Kontent.ai、Hygraph、Box、Frontify、Acquia DAM、Aprimo |
| 把元数据与品牌规则从“文档”升级为“可执行的运行时约束” | Contentstack Knowledge Vault、Sitecore Brand Kits、Aprimo Compliance Agent、Bynder Compliance Agent、Adobe Brand Aware Metadata |
| 把 GEO / AI 搜索可见性做成 CMS 内置功能 | Adobe LLM Optimizer、Optimizely（llms.txt 自动生成）、Progress Sitefinity SEO Agent、Sitecore 收购 Scrunch |

**分析师判断**：
- Gartner：到 2026 年，因缺乏 AI-ready 数据，组织将放弃 60% 的 AI 项目。
- Forrester：把 DAM 从“创意团队的素材库”重新定义为“内容的 system of action”。

### 3.3 八个核心判断与对我们的含义

| # | 附录 A 的判断 | 对我们的含义 |
|---|---|---|
| 1 | CMS / DAM 正在被重新定义为“Agent 的内容知识层”，而不是人的编辑台 | 产品定义要从“页面产出”上移到“可被机器消费的内容与规则” |
| 2 | 结构化内容与元数据是新护城河，并已被分析师定量化 | 内容建模、事实插槽、机器可读摘要是核心能力 |
| 3 | MCP Server 已成为内容平台的标准交付通道，**权限模型才是分水岭** | MCP 是必选项；做细权限分级、读写分离、访问日志 |
| 4 | 品牌治理与内容溯源从“加分项”变成“准入项” | Brand Voice 要能执行和检查；AI 内容要标识、可追溯 |
| 5 | GEO 正在反向重构内容结构，但工具化程度远超实证效果 | 押注结构化数据（JSON-LD）、问答式内容块和被引用量，不押注 llms.txt |

## 四、调研结论：产品定位与需求输入

**定位**：内容 CMS 只做价值链里的“CMS 生产与统一管理”两环，其他环节对接别的平台：
- 知识治理对接 KDH；
- 站点与运行时对接门户；
- Agent 能力对接 SEO / GEO / SDR；
- 效果与归因对接数据底座；
- 账号、计量、网关对接业务平台。

**差异化**，来自 KA 的“一份事实源”与附录 A 指出的行业空白：
1. 内容中的关键数值引用 KDH 授权事实，版本保存事实快照；
2. 事实变更自动联动内容复核；
3. 发布门禁以事实为主，红线人工确认；
4. MCP 分级权限与全链路审计。

**需求输入**，对应 PRD 章节：

| 来源 | 需求 | PRD 章节 |
|---|---|---|
| KA 价值链 ③④ | 选题、生成、编辑、翻译、一稿多用；模型、内容、审批、门禁、多语种、多站点 | 第 4.2、4.3、4.6 节 |
| KA 一份事实源 | 只引用授权事实；联动复核；模型 / 权限 / 审计一套 | 第 4.4、5 章 |
| KA 内容供应链 | 选题 → 生产 → 审批 → 发布 → 复盘闭环 | 第 6 章 |
| HubSpot 蓝本 | 第二节 37 项对标功能 | 第 4 章、第 9 章 |
| 附录 A 行业方向 | MCP 分级、规则可执行、GEO 结构化、AI 标识与审计 | 第 4.7、5 章 |
| KA 约束 | 三种部署形态同一基线、信创兼容、平台基础设施不重复建设 | 第 8 章 |
