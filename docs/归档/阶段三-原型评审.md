# 内容中台原型评审（v1，2026-11-19）

评审对象：`prototype/`，共 26 个页面。
对照依据：
- `阶段二-信息架构.md`：站点地图、关键流程 A–E、角色可见性
- `阶段二-整体架构.md`：KA 六组能力分工、内置 Agent
- `B2B KA 业务解决方案设计参考.docx`

评审方式：
- 静态扫描：按钮、跳转、mock 数据
- 浏览器逐页查看：1440 宽和 390 宽
- 手动走查关键流程

## 结论

**框架可以拿去评审，但演示数据要先统一。**

先说做得好的：
- 差异化主线（事实 → 冲突 → 内容 → 审核 → 供给）的页面齐全，彼此能跳转。
- 每页都有明确的"拦截点"：发布检查、红线确认、越界 403、导入预检。

要先修的问题：
- 前后两批页面用了两套产品故事，同一个内容 ID 在不同页面指向不同内容。
- 评审时一点就会穿帮，这是最需要先修的。

## 三、覆盖缺口（对照 KA 要求与站点地图）

| 要求 | 现状 | 影响 | 建议 |
|---|---|---|---|
| ⑤ 体验与个性化：**内容变体、实验标识**（中台负责数据结构，门户负责运行时分流） | 内容模型里有"变体"字段类型，但编辑器里**没有编辑变体的界面** | KA 要求像 HubSpot 那样支持 Smart Content / A/B 测试，这是和门户团队划分职责的关键点 | 在编辑器加"变体"标签页：按受众 / 地区 / 来源定义多个版本，加实验标识 |
| ① 多站点、hreflang | 只有"渠道"维度，没有站点维度，也没有 hreflang 关系 | 全球站点是 KA 的第一组能力 | 在语种版本标签页显示 hreflang 对应关系；渠道下细分到站点 |
| 内容供应链第一环：**选题** | 没有对应页面；选题助手和巡检 Agent（整体架构 7.4）也没有入口 | 价值链"知识 → 生产"的起点缺失 | 在 AI 生产下加"选题建议"，依据知识缺口、买家高频问题和健康度 |
| 内容详情的「审批记录」 | 编辑器只有 5 个标签页，缺审批记录 | 审计链条不完整 | 合并到"版本历史"，或单独加一个标签页 |
| 连接器详情（字段映射、同步日志）、调用方详情 | 只有列表和卡片 | 集成和供给的配置深度看不出来 | 至少各补一个详情页或侧栏 |
| 开发者能力：环境（开发 / 预发 / 生产）与模型迁移 | 内容模型有"导出变更"，但没有环境切换 | KA 3.3.2 要求 CLI 与 CI/CD | 在设置里加"环境"页：显示各环境差异，支持推送变更 |
| 回收站、生成任务记录 | 没有 | 影响小 | 放到 P2 |

## 四、关键流程走查

| 流程 | 能不能走通 | 断点 |
|---|---|---|
| A 基于事实生成内容 | ✅ 工作台 → 模板生成 → 编辑器 → 送审 | 送审之后看不到"生效 → Webhook 通知"的结果 |
| B 事实变更传导 | ◐ 事实库、冲突、复核队列都有 | 缺"影响分析"这一步：事实改动后看不到"插槽自动刷新 N 条 / 生成复核 M 条"的汇总（自动化流程 FL-01 的运行记录里有一行，但不在主路径上） |
| C 冲突处理 | ✅ 完整 | 处理完后不能跳到受影响的复核任务 |
| D 资产入库与跟踪 | ✅ 导入、AI 队列、事实候选都有 | "源已更新 → 确认替换"没有入口 |
| E 下游调用 | ✅ 调用方、MCP 分级、越界 403、日志都有 | 新建调用方之后看不到密钥只显示一次的处理 |

## 五、建议在评审会上请大家决定的问题

原型已经能展示下面几个问题各个选项的效果，适合在评审会上定下来：

1. **一级菜单是否合并**：现在有 10 组。「设置」下有 8 项，「洞察」只有 3 项。洞察是否并入工作台？（信息架构待确认第 1 条）
2. **插槽引用自动刷新后，新版本免审还是简审**：会影响复核队列的工作量。（待确认第 3 条）
3. **事实负责人是独立角色，还是由品牌管理员兼任**。（待确认第 4 条）
4. **与门户的分工线**：变体、实验、站点、hreflang 由谁负责到什么程度。这决定第三节前两项要不要补。
5. **支持的最小屏幕宽度**。
