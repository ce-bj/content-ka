## 1. 自研边界：自研的是"内核"，不是所有东西

| 自研（差异化与核心控制） | 采用成熟开源库（许可证友好） | 复用平台基础设施 |
|---|---|---|
| 模型引擎、字段类型系统 | 富文本编辑器：Lexical 或 Tiptap 核心（MIT） | 统一账号与 SSO |
| 权限引擎（策略 + 范围 + 字段 + 行） | 数据访问：多方言查询构建器（如 Kysely，MIT） | 权益与计量 |
| 版本与发布引擎、工作流引擎 | 校验：JSON Schema 校验器（如 Ajv，MIT） | API / MCP 网关 |
| 钩子与事件总线、自动化流程 | GraphQL：graphql-js（MIT） | 模型网关 |
| 事实、冲突、引用、影响分析 | 任务队列：BullMQ / pg-boss（MIT） | Agent 运行与治理 |
| 同步引擎与连接器 SDK | 图片处理 sharp（Apache 2.0）、音视频 FFmpeg（LGPL，独立进程调用） | |
| 供给层（API、MCP、Webhook）与调用留痕 | OCR：PaddleOCR（Apache 2.0，中文强） | |
| 管理后台框架（列表框架、编辑器外壳、字段组件注册） | 语音转写：Whisper / FunASR | |
| | 向量模型：bge-m3（MIT，多语种） | |
| | 检索：OpenSearch（Apache 2.0）、pgvector | |

**原则**：开源库只用 MIT / Apache 2.0 / BSD 类许可；AGPL、BSL、SSPL 类许可的组件不打进私有化包（例如 MinIO 为 AGPL，需法务评估后再定）。FFmpeg 以独立进程调用，避免 LGPL 链接问题。

## 2. 技术栈

| 层 | 推荐 | 理由 |
|---|---|---|
| 内核与 API 服务 | **TypeScript（Node.js）** | 内容模型、字段、校验都是 JSON 结构，前后端共用类型与校验规则；可直接参考 Payload / Strapi / Directus 的实现 |
| 管理后台 | React + TypeScript | 字段组件注册、动态表单；编辑器生态成熟 |
| AI 服务 | Python | OCR、转写、识图、向量化的模型生态都在 Python；作为独立服务，经任务队列调用 |
| 关系库 | PostgreSQL（主）；人大金仓、达梦（适配） | 见第 3.4 节 |
| 部署 | 容器（x86 / ARM 双架构镜像），Helm 与离线安装包 | 满足三种部署形态 |

> **需要确认**：如果团队现有主力栈是 Java，或**达梦为硬性要求**（Node 生态的达梦驱动成熟度明显弱于 Java），可改用 Java（Spring Boot）实现内核。架构和数据设计不变，只是借鉴开源项目的代码时需要转译。建议在技术验证（第 7 节 M0）里一并验证。

## 3. 数据设计

### 3.1 关键决定：内容存储方式

| 方案 | 说明 | 结论 |
|---|---|---|
| 每个内容类型一张表（Directus / Strapi 做法） | 改模型 = 改表结构 | 不采用：多租户下表数量爆炸，模型变更要做 DDL，国产库 DDL 行为差异大 |
| 内容存 JSON + 依赖 PostgreSQL JSONB 运算符查询 | 查询灵活 | 不采用为唯一方案：达梦等库对 JSONB 支持有限，会锁死数据库 |
| **内容存 JSON 文档 + 独立的"字段索引表"** | 字段值整体存 JSON；声明为"可筛选/可排序"的字段，写入时同步拆到索引表（字段路径、文本值、数值、日期值） | **采用**：只依赖标准 SQL，各数据库都能跑；PostgreSQL 上可额外加 JSONB 索引做加速 |

### 3.2 核心表

所有业务表都带 `tenant_id`；范围相关的表带 `org_unit_id`、`region`、`locale`。

**模型**

| 表 | 关键列 |
|---|---|
| content_type | id, tenant_id, api_id, kind（多条/单例/数据表）, schema（JSON：字段定义）, schema_version, status |
| component | id, tenant_id, api_id, schema, schema_version |
| schema_changeset | id, tenant_id, target, from_version, to_version, ops（JSON：加字段、改名、改类型…）, applied_at |

**内容**

|---|---|

| entry_version | id, variant_id, version_no, schema_version, data（JSON）, state（草稿/审核中/已生效/已替代）, ai_marks（JSON：哪些路径为 AI 生成）, check_result（JSON）, created_by, created_at |

### 3.3 版本存储规则

- 版本行**不可变**：送审时冻结当前草稿为一个版本；草稿阶段的自动保存只更新草稿行。
- 每个语种变体各自有"最新版本"和"已生效版本"两个指针；新版本审核期间，旧的已生效版本继续对外提供。
- `reference.snapshot` 在发布时固化，保证"这个版本当时引用的取值"永远可查。
- 版本记录 `schema_version`；模型变更后，读旧版本时按变更集**读时升级**，后台任务再批量迁移。

### 3.4 数据库适配

| 能力 | PostgreSQL | 人大金仓（兼容 PG 模式） | 达梦 |
|---|---|---|---|
| JSON 存储 | JSONB | JSONB（需验证） | 文本/CLOB 存 JSON |
| 字段筛选 | 字段索引表 + 可选 JSONB 索引 | 字段索引表 | 字段索引表 |
| 全文检索 | 内置 + 中文分词扩展，或 OpenSearch | 需验证 | OpenSearch |
| 向量 | pgvector | 需验证 | 独立向量库 |
| 行级隔离 | 应用层 tenant_id 过滤（统一做法） | 同左 | 同左 |

**所有数据库都只走"标准 SQL + 字段索引表"这条公共路径**，特有能力只做加速，不做依赖。

## 4. 各引擎实现要点

### 4.1 模型引擎

- 字段定义用**统一的字段描述结构**（类型、校验、多语种、条件显示、权限规则、AI 辅助、是否可筛选），由它派生出：
  - 后端 JSON Schema 校验规则；
  - 后台动态表单；
  - GraphQL 类型与 REST 文档；
  - MCP 工具的参数定义；
  - 字段索引表的拆分规则。
- 变更流程：编辑模型 → 生成变更集 → 影响评估（多少条内容受影响、是否有破坏性变更）→ 确认 → 生效。破坏性变更（删字段、改类型）需二次确认并保留旧数据。
- 变更集可导出为文件，用 CLI 在环境之间迁移，进 Git 管理。

### 4.2 字段类型注册

每种字段类型实现同一组接口：`校验`、`序列化/反序列化`、`拆分索引值`、`对外输出`、`后台组件`、`AI 生成提示`。内置类型和 FDE 扩展的类型走同一套注册机制。事实插槽、资产引用、变体是内置的特殊类型：它们在保存时写 `reference` 表，在读取时按调用方范围解析。

### 4.3 权限引擎

```
请求（用户 / 调用方令牌 / Agent）
  → 解析身份 → 收集策略（角色策略 + 用户附加策略 + 令牌策略）
  → 编译为：① 允许的操作集合 ② 查询条件（tenant + 范围 + 状态） ③ 字段掩码
  → 列表查询：条件拼进 SQL；读详情：校验 + 字段掩码；写入：校验 + 红线字段拦截
  → 编译结果按"身份 + 策略版本"缓存
```

借鉴 Payload：访问规则可以返回"查询条件"而不只是是/否，从而在数据库层完成行级过滤，避免先查后滤。

### 4.4 钩子与事件总线

- **同步钩子**（在事务内）：校验前、保存前 —— 用于校验、红线拦截、插槽解析。
- **异步事件**（事务外）：保存后、发布后、下线后、外部变更 —— 用**事务外发表（outbox）**：业务写入和事件写入同一事务，再由投递进程发到队列。保证"数据写了，事件一定发"。
- 事件消费者：Webhook 投递、检索与向量索引、影响分析、自动化流程、审计、回灌知识库（D4 待定）。
- Webhook 带签名、重试（指数退避）、死信可重放。

### 4.5 工作流引擎

不引入 BPMN 引擎。用**可配置的阶段状态机**：阶段、每阶段的处理人规则（角色 + 范围）、通过条件（任一/全部）、可执行动作（通过、驳回、加签、紧急放行）、**阶段权限**（谁能把内容推进到该阶段——用于限制 Agent 跳过人工）。审批与复核共用待办（task）模型。

### 4.6 自动化流程

- 触发器：数据事件、定时、Webhook、手动、其他流程。
- 操作：条件、读写内容、创建任务、通知、HTTP 请求、调用 AI 能力、调用外部 MCP 工具、运行函数。
- 函数在沙箱里运行（限时、限内存、无文件系统，只能调白名单接口）；有平台运行时就交给平台。
- 内置模板：事实到期提醒、源资产更新后替换、发布后通知渠道、新资产自动 AI 处理。

### 4.7 供给层

| 接口 | 实现要点 |
|---|---|
| Delivery API（REST + GraphQL） | 只返回已生效版本；GraphQL schema 按租户由模型动态生成并缓存，模型变更时失效；响应可被 CDN 缓存，发布事件触发清除 |
| Preview API | 可读草稿，令牌短时有效 |
| Management API | 后台本身也走这套接口（"后台即第一个 API 用户"），保证接口完整 |
| MCP Server | 工具由模型引擎派生（每个内容类型自动生成"搜索/读取/创建草稿"工具）；三级权限；经平台 MCP 网关对外 |
| 效果回流 API | 按内容 ID + 版本 + 渠道接收效果事件，聚合后进洞察 |

### 4.8 同步引擎

- 连接器 SDK 定义统一接口：鉴权、列表与增量游标、读取、写回（可选）、变更通知。
- 同步流程：拉取 → 字段映射 → 比较外部版本 → 写入本地并更新 `source_trace` → 发事件。
- 双向事实同步：版本号比较；双方都改 → 生成冲突（⑤）；带"修改来源"标识防回环。
- 每个连接器独立限速、独立失败重试，互不影响。

### 4.9 检索

- 写入：发布或保存事件 → 抽取文本（含 OCR、字幕结果）→ 分词 → 全文索引；同时向量化 → 向量索引。
- 查询：关键词与向量混合召回 → 按权限条件过滤 → 重排 → 返回匹配原因。
- 中文分词与多语种需要专门处理（中英德等）。

## 6. 质量与非功能要求

| 项 | 目标（建议值，待定） |
|---|---|
| Delivery API 延迟 | 有缓存 P95 < 100ms；无缓存 P95 < 300ms |
| 单租户规模 | 内容 100 万版本、资产 50 万、事实 10 万 |
| 可用性 | SaaS 99.9%（KA 方案对标 99.99% 的部分由门户与 CDN 承担） |
| 审计 | 所有写操作和对外调用 100% 留痕 |
| 测试 | 内核单元测试覆盖率 ≥ 80%；每个数据库方言跑同一套集成测试 |
| 安全 | 多租户隔离测试、MCP 提示注入防护（工具输入输出过滤、高风险工具人工确认） |

## 7. 研发里程碑（建议）

以第二阶段出口（2027 年 6 月末，样板客户完整上线）倒推，并留出 KA 项目 13 周部署窗口。

| 里程碑 | 时间 | 内容 | 出口标准 |
|---|---|---|---|
| **M0 技术验证** | 2026-12 | 字段索引表方案的查询性能；人大金仓、达梦适配；动态 GraphQL 性能；技术栈定稿 | 三种数据库跑通同一套核心用例 |
| **M1 内核骨架** | 2027-01 ～ 02 | 模型引擎、字段类型、存储、权限、版本、事件总线；后台列表框架与编辑器外壳 | 能建模型、录内容、走版本、按范围控权限 |
| **M2 差异化核心** | 2027-02 ～ 03 | 事实、冲突、引用与影响分析、发布检查、工作流 | 事实变更能传导到内容复核 |
| **M3 资产与集成** | 2027-03 ～ 04 | 资产库与 AI 流水线、连接器 SDK、KDH 双向同步、首批连接器 | 证书 OCR → 事实候选跑通 |
| **M4 供给与生产** | 2027-04 | Delivery/Preview API、MCP、Webhook、AI 生产、自动化流程、洞察 | 门户与一个 Agent 能接入取内容 |
| **M5 交付就绪** | 2027-05 ～ 06 | 私有化打包、国产化兼容清单、性能与安全测试、样板客户部署 | 样板客户上线 |

> 节奏很紧：KA 方案要求企业版能力"一次性完整交付"，这份排期按"所有能力都在 6 月末前做完"倒推。若 M0 发现国产库或性能问题，最先受影响的是 M5。建议 M0 结束时根据人力复核排期。

## 8. 主要风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 自研范围大、时间紧 | 样板客户延期 | 严格按第 1 节边界，非核心一律用成熟库；编辑器不自研 |
| 达梦兼容 | 私有化样板受阻 | M0 验证；必要时达梦客户走"标准 SQL 路径 + 外置检索" |
| 动态 GraphQL 与多租户缓存 | 性能与内存 | 按租户懒加载、模型变更时局部失效 |
| 中文与多语种检索质量 | 自然语言搜索体验差 | 选型时用真实制造业资料做评测集 |
| AI 能力的私有化 | 本地模型效果与资源占用 | 为私有化准备轻量模型组合，并给出硬件清单 |
| MCP 安全 | 提示注入、越权 | 工具三级权限、高风险强制人工、输入输出过滤、全量留痕 |
| 开源组件许可证 | 私有化分发合规 | 建立组件许可证清单，AGPL/BSL/SSPL 类组件不入包 |

## 9. 待确认

1. 技术栈：TypeScript（推荐）还是 Java？取决于团队主力栈和达梦是否为硬性要求。
2. 第 6 节的非功能指标是否认可，尤其单租户规模。
3. 第 7 节里程碑与团队人力是否匹配（需要研发负责人评估）。
4. 平台基础设施（账号、计量、MCP 网关、模型网关、Agent 运行时）各自的就绪时间——直接决定 M1、M4 能否按期。
