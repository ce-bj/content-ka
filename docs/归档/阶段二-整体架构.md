## 0. 本版的三处调整

| # | 调整 | 原因 |
|---|---|---|
| 1 | **明确"内容中心企业版 = 内容中台 + 站点体验层"** | KA 方案要求内容中心企业版完整覆盖六组能力（含多站点、Smart Content、A/B），而 D1 已定中台只做供给。两者不矛盾：中台负责内容与治理，站点体验层（AI 门户）负责渲染与个性化执行，同属 AI 原生企业官网产品组。第 2 节逐项列出谁负责 |
| 2 | **资产库增加 AI 理解能力**（D11 扩展） | 外部素材已复制到本地（D8），且很多客户没有 DAM，本地资产就需要 OCR、识图打标、视频字幕摘要、自然语言搜索。证书和检测报告的 OCR 结果还能直接变成事实候选 |
| 3 | **自研内容内核，借鉴三个开源项目的设计**，不直接基于某一个二次开发 | 见第 4 节：多租户 SaaS 需要"运行时可配置的内容模型"，Payload/Strapi 的模型定义在代码里，改模型要重新部署；Directus 运行时可配，但许可证对大客户收费；KA 还要求三种部署形态同一代码基线、国产数据库兼容 |

| 来源 | 要求 |

## 4. 开源项目借鉴

### 4.1 结论先行

| 项目 | 许可证 | 最值得借鉴 | 不直接采用的原因 |
|---|---|---|---|
| **Payload** | MIT（2025 年被 Figma 收购，官方表示保持开源） | **内核设计**：字段系统、访问控制函数、钩子生命周期、版本与草稿、多租户插件 | 内容模型写在代码里，改模型要重新构建和部署；客户管理员无法在界面上自助建模。与 Next.js 深度绑定 |
| **Strapi** | 社区版 MIT；审批流、SSO、审计日志属于企业版付费功能 | **产品功能与交互**：可视化内容模型设计器、媒体库、草稿/发布、发布批次、插件市场、API 令牌；内置 MCP | 内容模型设计器只在开发模式可用，生产环境改模型同样要重新部署；企业级治理能力不在开源部分 |
| **Directus** | 商业源码许可（v11 为 BSL，v12 改为 MSCL），年营收 500 万美元以上的组织需付费 | **数据管理后台**：运行时建表、多种列表视图与筛选、文件管理与图片变换、基于策略的权限、Flows 自动化；原生 MCP 走现有权限 | KA 客户营收普遍远超阈值，嵌入商用需购买授权；以数据库表为中心，内容治理（审批、版本、多语种工作流）偏弱 |

**已决定（D12，2026-11-19）：内核自研。** 技术方案见 [阶段二-内核技术方案.md](阶段二-内核技术方案.md)。

**原建议**：内核自研，采用"**内容模型即数据**"（模型定义存数据库、运行时生效，内容以 JSONB 存储，Contentful / Contentstack / Storyblok 等 SaaS CMS 都是这条路线），同时把下面这些设计借鉴进来。这样才能同时满足：多租户 SaaS 下每个客户自助建模、私有化同一代码基线、国产数据库兼容，以及事实、冲突、引用这些差异化能力深度嵌入内核。

> 如果更看重上线速度，备选方案是 **基于 Payload 二次开发**（许可证最友好、内核设计最接近）。代价是要自己补"运行时建模"，且后续升级受上游影响。建议在第 10 节问题 2 中拍板。

### 4.2 Payload：内核设计

| Payload 设计 | 我们怎么用 | 落到哪 |
|---|---|---|
| **Collection / Global** | Collection = 多条内容的内容类型（产品说明、FAQ）；Global = 单例内容（品牌信息、页脚联系方式、法律声明） | 内容模型增加"单例类型" |
| **字段类型**：text、richText（Lexical）、number、select、relationship、upload、array、**blocks**、group、tabs、json、join | 字段类型系统直接参照，再加我们的三种：**事实插槽**、**资产引用**（带授权与同步状态）、**变体** | 字段类型系统 |
| 字段的 `admin` 配置（条件显示、只读、描述、自定义组件） | 动态表单：字段条件显示、按角色只读、字段说明 | 编辑器 |
| **访问控制**：每个 Collection、每个字段都有 read/create/update/delete 函数，可返回布尔值或**查询条件**（实现行级权限） | 权限引擎的核心思路：权限 = 角色 × 操作 × **范围条件**（品牌/区域/语种）；字段级权限用于价格、交期等红线字段 | 权限引擎 |
| **钩子生命周期**：beforeValidate → beforeChange → afterChange → afterRead；beforeDelete → afterDelete；以及登录、操作类钩子 | 把发布检查、事实快照、影响分析、Webhook 都挂在钩子上；对外开放给 FDE 写定制逻辑（对应 KA 的 Serverless Functions） | 钩子与事件总线 |
| **版本、草稿、自动保存、定时发布** | 版本引擎直接参照；加上"事实快照"和"生成依据"随版本保存 | 版本与发布引擎 |
| **本地化**：字段级 `localized: true` | 指定哪些字段多语种，非多语种字段各语种共享（如型号、参数表） | 本地化 |
| **多租户插件** | 租户 = 客户；租户内再分品牌/事业部 | 范围模型 |
| **Live Preview** | 编辑器里嵌入门户的预览地址，实时显示 | 编辑器 |
| **任务队列（Jobs）** | AI 生成、翻译、OCR、同步等长任务统一排队 | 任务队列 |
| **自定义 Admin 组件**（React 组件替换任意视图/字段） | 预留扩展点：FDE 可为特定客户替换字段组件或增加视图，但不改内核（符合 KA"FDE 不写产品内核"） | 应用层扩展点 |

### 4.3 Strapi：产品功能

| Strapi 功能 | 我们怎么用 | 落到哪 |
|---|---|---|
| **可视化内容模型设计器**（Content-Type Builder）；2025 起有 AI 根据自然语言生成模型 | 设置 → 内容模型的交互蓝本；加 AI 建模：描述"我要一个技术 FAQ 类型" → 生成字段草案 → 人确认；**生产环境也能改**（我们的差异） | 设置 → 内容模型 |
| **组件与动态区** | 组件 = 可复用内容块；动态区 = 编辑者自由组合块（用于落地页内容） | 字段类型系统 |
| **媒体库**：文件夹、上传、裁切、多尺寸、alt；上传提供方插件（S3 等） | 资产库基础交互；存储适配器（S3 兼容 / 国产对象存储） | 资产库 |
| **草稿与发布、Releases（批量发布）** | 发布批次 | 版本与发布 |
| **审批流程（Review Workflows）**：自定义阶段、阶段权限 | 审批引擎参考；阶段权限可用于限制 Agent 令牌跳过人工阶段 | 工作流引擎 |
| **i18n** | 语种变体管理界面 | 多语种 |
| **API 令牌**（只读 / 完全 / 自定义） | 调用方密钥分级 | 供给 → 调用方 |
| **插件市场** | 第三阶段考虑：连接器和字段组件以插件形式上架 | 生态 |
| **内置 MCP**（以管理员令牌与角色权限控制） | 印证 MCP 应走与人相同的权限体系 | MCP Server |
| 内容历史、审计日志 | 版本对比与审计 | 审计 |

### 4.4 Directus：数据管理后台

| Directus 功能 | 我们怎么用 | 落到哪 |
|---|---|---|
| **运行时建表**（改模型立即生效、自动迁移） | "内容模型即数据"的参照：模型变更即时生效，并自动生成变更记录，可导出到其他环境 | 模型引擎 |
| **多种列表视图**：表格、卡片、日历、看板、地图；可保存的筛选与视图（书签） | 所有列表页统一框架：表格 / 卡片（资产）/ 日历（定时发布）/ 看板（审批状态）；**保存视图**按人或按角色共享 | 列表框架 |
| **数据表管理** | KA ② 的"数据表与动态页面"：产品目录、伙伴名录、资源库作为**数据表型内容类型**，支持表格内编辑、批量导入导出 | 内容 → 数据表 |
| **文件管理与图片变换**（按 URL 参数裁切、缩放、格式转换） | 资产渲染地址支持按参数输出多尺寸与 WebP | 资产库 |
| **基于策略的权限**（策略可挂在角色或用户上，可叠加） | 权限 = 多个策略叠加，便于"品牌管理员 + 某区域审核"这类组合身份 | 权限引擎 |
| **Flows 自动化**：触发器（数据事件、Webhook、定时、手动、其他流程）+ 操作（条件、脚本、HTTP 请求、通知、读写数据…） | **自动化流程**：把复核触发、到期提醒、同步后处理、通知等做成可配置流程；内置一批模板，FDE 可为客户配置（对应 KA 的 Serverless Functions 低代码版） | 设置 → 自动化 |
| **Insights 仪表盘** | 洞察页面的可配置面板 | 洞察 |
| **原生 MCP**（走现有权限体系） | 同上，印证权限一致原则 | MCP Server |
| 可接任意 SQL 数据库 | 数据库适配层的参考（国产库兼容） | 存储层 |

## 5. 内容内核设计要点

### 5.1 模型引擎（内容模型即数据）

- 内容类型、组件、字段定义存在数据库，**运行时生效**，不需要重新部署。
- 内容存储：通用字段（ID、类型、范围、状态、版本号、时间）用列；字段值用 JSONB；需要筛选排序的字段建索引。
- 模型变更自动生成**变更集**，可导出为文件、纳入 Git，用 CLI 迁移到其他环境（满足 KA 的 CLI 与 CI/CD）。
- 内容类型分三种：**多条型**（产品说明、FAQ）、**单例型**（品牌信息、法律声明）、**数据表型**（产品目录、伙伴名录：表格编辑、批量导入）。

### 5.2 字段类型

| 类别 | 字段 |
|---|---|
| 基础 | 单行文本、多行文本、富文本（块编辑器）、数字、布尔、日期、枚举、标签、JSON、链接、颜色 |
| 结构 | 组、数组、标签页、**组件**、**动态区**（自由组合组件） |
| 关联 | 内容引用（一对一 / 一对多 / 双向）、**资产引用**、**事实插槽**、事实列表（参数表） |
| 体验 | **变体**（按受众/地区/来源的多个取值）、个性化令牌占位、访问级别 |
| AI 与可见性 | 摘要（机器可读）、Q&A 列表、结构化数据映射 |

每个字段可配：必填、校验规则、是否多语种、条件显示、按角色只读、说明文字、AI 辅助（可生成/可改写）。

### 5.3 权限引擎

```
权限判定 = 策略叠加（角色策略 + 用户附加策略）
策略 = 功能（菜单/操作） × 对象类型 × 操作（读/建/改/删/送审/发布/下线）
       × 范围条件（品牌、区域、语种、渠道）
       × 字段规则（可见 / 只读 / 隐藏）
调用方（API / MCP）与 Agent 走同一套判定：令牌绑定一组策略
```

### 5.4 钩子与事件

| 时点 | 内置处理 |
|---|---|
| 校验前 / 保存前 | 字段校验、红线字段拦截、事实插槽解析 |
| 保存后 | 声明抽取与内容 vs 事实比对（冲突 ②）、健康度更新、向量索引更新 |
| 送审时 | 发布检查 |
| 发布后 | 事实快照固化、Webhook、缓存刷新、（D4 确定后）回灌知识库 |
| 读取后 | 按调用方范围过滤字段与变体、AI 标识附加 |
| 外部变更（同步、事实变更、资产变更、授权到期） | 影响分析 → 复核任务或插槽自动刷新 |

钩子对外开放两种扩展方式：**自动化流程**（低代码，客户管理员和 FDE 配置）、**函数**（代码，FDE 编写，沙箱运行，经平台运行时）。

### 5.5 版本与发布

草稿 → 审核中 → 已生效 → 已下线；自动保存；版本对比与回滚；定时发布/下线；发布批次；开发/预发/生产三环境，环境间内容与模型可迁移。

### 5.6 工作流引擎

审批链按"范围 × 内容类型"匹配；节点支持串行、会签、或签、加签、驳回、紧急放行；**阶段权限**限制谁（包括 Agent）能把内容推进到哪一步；红线动作强制人工节点。

## 6. 数字资产与 AI 理解（对应新输入的能力清单）

### 6.1 资产处理流水线

```
上传 / 导入副本
   → 基础处理：格式识别 · 缩略图 · 多尺寸 · 视频转码（分发版）
   → AI 理解（异步任务，可按资产类型开关）
       图片：识图打标 · 场景/产品识别 · 文字识别（OCR）· 自动生成 alt（多语种）· 相似图与重复检测
       文档：OCR · 版式解析（表格、段落）· 摘要 · 证书/检测报告字段抽取 → 生成"事实候选"
       视频：语音转写 · 多语种字幕 · 摘要 · 关键帧与章节
       音频：语音转写 · 摘要
   → 向量化（文本 + 图像）进入语义索引
   → 人工确认（AI 标签与抽取结果显示置信度，可改）
   → 可用
```

**和事实打通**：证书、检测报告、产品手册经 OCR 抽取出的参数（证书编号、防护等级、有效期），作为**事实候选**进入事实库待确认，证据原件自动关联该资产。这是 B2B 制造业场景的关键价值点。

### 6.2 自然语言搜索

- 一个搜索框同时搜内容、资产、事实；支持"去年欧盟展会上 BL-R600 的现场照片""带 CE 标志的产品图"这类描述。
- 实现：关键词 + 向量的混合检索，再按权限范围过滤，结果标注匹配原因（命中标签 / 命中字幕 / 画面相似）。

### 6.3 "选择素材自动生成营销页面"怎么落地

中台不渲染页面（D1），所以做成：**选择素材与事实 → AI 生成一条"落地页"类型的结构化内容**（由组件组成：首屏、卖点、参数表、案例、视频、CTA）→ 审核 → 门户按组件渲染。在编辑器里通过门户预览地址看到页面效果。

### 6.4 "发布到官网、App、小程序"怎么落地

每个渠道注册为一个**调用方**，绑定授权范围与输出格式；内容生效后通过 Webhook 通知，渠道用 API 拉取。小程序、App 用同一套 Delivery API，图片按渠道取不同尺寸。

### 6.5 和 D3 的关系

D3（不自建 DAM）仍然成立：中台不做专业 DAM 的深度功能（品牌门户、复杂版权工作流、创意审稿批注、海量素材分发）。但本地资产库具备**够用的 AI 理解能力**，覆盖没有 DAM 的客户和"导入副本"后的素材。

## 7. MCP 与 AI 接入

### 7.1 两个方向

| 方向 | 用途 | 说明 |
|---|---|---|
| **中台作为 MCP Server** | 让 SEO/GEO Agent、SDR Agent、社媒 Agent，以及客户自己的 Claude / Copilot / ChatGPT 读写内容 | 经平台 API/MCP 网关对外；与人走同一权限引擎 |
| **中台作为 MCP 客户端** | 调用 KDH 的知识检索、外部翻译/识图服务、客户内部工具 | 经平台网关；在设置中登记可用的外部 MCP 工具 |

### 7.2 MCP Server 工具清单（按权限分三级，借鉴 Storyblok）

| 级别 | 工具 |
|---|---|
| **只读** | 搜索内容、按范围取已生效内容、取内容版本与引用事实、搜索资产、取资产地址、查事实、查内容模型、查健康度问题 |
| **写入** | 创建草稿、更新草稿、上传资产、提交事实候选、创建翻译任务、送审 |
| **高风险**（默认关闭，需管理员显式开启，且强制人工确认） | 发布、下线、删除、修改事实、修改内容模型 |

所有 MCP 调用记录：哪个调用方、哪个 Agent、代表哪个用户、调了什么、结果如何。

### 7.3 AI 能力接入原则

- **模型可替换**：经平台模型网关接入；私有化场景接本地模型；支持客户自带模型和密钥。
- **能力即服务**：生成、翻译、抽取、OCR、识图、转写、向量化各为独立服务，经任务队列调用，失败可重试。
- **人工在环**：AI 结果默认为草稿或候选；红线字段与高风险动作强制人工确认。
- **AI 标识**：AI 生成或修改的段落、资产带标识，随版本保存、随 API 下发（满足 KA 5.4 和 EU AI Act 第 50 条透明度义务）。
- **计量**：每次 AI 调用按租户、功能记录用量，上报平台权益与计量（KA 5.3）。
- **数据不出域**：客户数据用于训练需合同授权；私有化下所有 AI 调用不出客户网络。

### 7.4 内置 Agent

| Agent | 做什么 | 人工节点 |
|---|---|---|
| 编辑助手 | 编辑器内改写、扩写、翻译、生成摘要与 Q&A、检查 Brand Voice | 编辑决定是否采纳 |
| 选题助手 | 基于知识缺口、买家高频问题、内容健康度建议选题 | 内容负责人确认 |
| 巡检 Agent | 定期扫描过期、冲突、缺语种、引用失效，生成复核任务 | 复核人处理 |
| 资产整理 Agent | 打标、去重、补 alt、抽取事实候选 | 资产负责人确认 |
| 翻译 Agent | 批量翻译、术语校验 | 区域审核 |

均运行在平台 Agent 运行时上（编排、评测、日志由平台提供）。

## 8. 部署架构

| 组件 | SaaS | 私有化（含信创） | 说明 |
|---|---|---|---|
| 应用服务 | 容器化，多租户 | 容器化，单租户 | 同一代码基线，按部署形态打包 |
| 关系库 | PostgreSQL | PostgreSQL / 人大金仓 / 达梦 | 数据访问层做方言适配；**国产库兼容需尽早验证**（JSONB 与全文检索差异最大） |
| 对象存储 | 云对象存储 | 客户已有的 S3 兼容存储，或随包提供的开源对象存储 | MinIO 为 AGPL 许可，随私有化包分发前需法务评估；备选 SeaweedFS（Apache 2.0）、Ceph |
| 全文检索 | 搜索引擎 | 同左或数据库内置全文检索 | 小规模客户可不单独部署搜索引擎 |
| 向量索引 | 向量扩展或独立向量库 | 同左 | |
| 队列与缓存 | Redis 类 | 同左 | |
| AI 模型 | 平台模型网关 | 本地模型 + 网关 | OCR、转写、识图需准备私有化可用的模型 |
| CPU 与操作系统 | x86 | x86 / ARM；麒麟、统信 | |

**混合部署**（KA 5.1）：中台应用与资产分发在云上，事实与敏感数据所在的 KDH 留在本地，通过专线或网关同步。
