## 1. 设计原则

1. **以内容为中心**：所有模块最后都落到"一条内容的一个版本"上，事实、资产、生成依据都挂在内容版本下面。
2. **范围是一等维度**：品牌 × 区域 × 语种（+ 渠道）贯穿事实、内容、资产、权限和调用，所有列表都能按范围筛选。
3. **外部数据本地化**：知识库、DAM 拉进来的数据都有来源追踪和同步状态，界面上统一用同一套状态标识。
4. **问题找人，不让人找问题**：冲突、过期、源变更、授权到期统一汇入工作台和复核队列。
5. **不做建站**：没有页面、主题、导航菜单编辑；只有内容预览（调用使用方的预览地址）。

## 2. 导航结构

### 2.1 一级菜单（10 个）

| # | 一级菜单 | 回答的问题 | 主要使用者 |
|---|---|---|---|
| 1 | **工作台** | 今天我要处理什么 | 所有人 |
| 2 | **内容** | 有哪些内容、编辑与发布 | 编辑、品牌管理员 |
| 3 | **AI 生产** | 怎么批量、规范地生产内容 | 编辑 |
| 4 | **事实** | 内容依据的事实是什么、有没有冲突 | 事实负责人、编辑 |
| 5 | **资产** | 图片、视频、文件在哪 | 编辑、品牌管理员 |
| 6 | **审核** | 哪些内容等我审、哪些要复核 | 合规、品牌、业务审核人 |
| 7 | **供给** | 谁在用内容、怎么接入 | 平台管理员、开发者 |
| 8 | **集成** | 外部系统接得怎么样 | 平台管理员 / IT |
| 9 | **洞察** | 内容质量与使用情况 | 内容负责人 |
| 10 | **设置** | 内容模型、组织、角色、规则 | 平台管理员 |

顶栏常驻：**范围切换器**（品牌 / 区域 / 语种）、全局搜索（内容、事实、资产）、通知、当前角色。

```
          │              │          │                         │
  对象 ◄──┤        内容类型 ◄─┤          │                         │

          │         │   │    │

  冲突 ──► 事实（①⑤）/ 内容版本（②③）

```

### 3.3 状态

**内容版本**

```
草稿 ──送审──► 审核中 ──通过──► 已生效 ──下线──► 已下线
  ▲              │                │
  └────驳回──────┘                └──编辑──► 新草稿版本（旧版本继续生效，直到新版本生效）
```
附加标记（可叠加）：`待复核` · `检查未通过` · `含 AI 生成` · `定时发布`

**事实**

```
待确认 ──确认──► 有效 ──到期──► 已过期
                 │
                 ├──冲突处理：被替代──► 已被替代（只读，保留历史）
                 └──冲突处理：暂停──► 暂停引用
```
附加标记：`冲突中` · 同步状态（见下）

**同步状态（事实、资产通用）**：已同步 ／ 源已更新 ／ 本地已修改 ／ 双方都改了 ／ 源已删除 ／ 同步失败 ／ 本地（无来源）

**资产**：待审 ／ 可用 ／ 授权到期 ／ 已停用（+ 同步状态）

## 5. 关键流程

### 流程 A：基于事实生成一条内容

```
内容 / AI 生产 → 模板生成
  ① 选内容类型与模板
  ② 选范围：品牌 · 区域 · 语种
  ③ 选事实（本地事实库，只显示范围内、有效、无冲突的；冲突与过期的灰显并说明原因）
  ④ 可选：知识库检索补充背景材料（显示片段与出处，勾选使用）
  ⑤ 生成 → 进入编辑器（事实以标签形式插入，AI 段落带标识）
  ⑥ 编辑器右侧"检查"面板实时显示发布检查结果
  ⑦ 送审 → 审核 → 生效 → Webhook 通知订阅的调用方
保存时：事实快照 + 生成依据 写入该版本
```

### 流程 B：事实变更传导到内容

```
知识库修改事实（或中台录入/修改）
  → 同步：比较版本
      ├─ 只有一方改了 → 自动同步
      └─ 双方都改了 → 生成冲突（⑤）→ 事实负责人处理
  → 新取值生效 → 影响分析（查"引用"）
      ├─ 插槽引用（参数表、规格卡）→ 自动刷新，生成新版本，按规则免审或简审
      └─ 正文引用 → 生成复核任务 → 审核 → 复核队列
  → 新版本生效 → Webhook 通知调用方
```

### 流程 C：冲突处理

```
事实 → 冲突处理 → 选一条冲突
  面板：两条取值并排 · 来源原件 · 证据等级 · 有效期 · 各自被哪些内容引用
        系统推荐值 + 推荐理由（命中哪条规则）
  动作：采纳 A ／ 采纳 B ／ 拆分适用范围 ／ 都暂停 ／ 发起源系统修正
  → 结果同步到知识库 + 记录决策 → 触发流程 B 的影响分析
```

### 流程 D：资产入库与跟踪

```
资产 → 从外部导入 → 选连接器 → 浏览/搜索（沿用源系统权限）
  → 导入副本（默认）或 仅引用 → 补充内容侧字段与授权 → 审核 → 可用
之后：源更新 → "源已更新" → 自动或确认后替换
      源删除 → "源已删除"，副本保留
      授权到期 → 引用它的内容进入复核，发布检查拦截
```

### 流程 E：下游调用

```
供给 → 调用方 → 新建：名称 · 授权范围 · 环境 · 接口 / MCP 权限级别 → 生成密钥
调用时：服务端按范围过滤 → 只返回"已生效"版本（Preview API 可取草稿）
        越界 → 403 + 原因 + 留痕
```

## 6. 关键页面布局要点

### 6.1 内容编辑器（最核心的页面）

```
┌ 顶栏：标题 · 类型 · 范围 · 语种切换 · 状态 · [预览] [保存] [送审] ┐
├──────────┬───────────────────────────────┬──────────────┤
│ 结构      │ 字段区                          │ 右侧面板（标签页）│
│ · 字段导航 │ · 表单字段                        │ · 事实：搜索并插入  │
│ · 组件列表 │ · 块编辑器（正文）                  │ · 资产：资产库选取  │
│          │ · 事实标签：悬停显示取值、证据、有效期    │ · AI：改写/扩写/翻译 │
│          │ · 资产卡片：显示授权与同步状态          │ · 检查：发布检查实时结果│
└──────────┴───────────────────────────────┴──────────────┘
```

### 6.2 冲突处理面板

左：冲突队列（按类型、影响内容数排序）。右：两条取值并排对比卡 + 推荐值 + 影响内容列表 + 五个处理按钮 + 处理依据输入框。

### 6.3 列表页统一框架

顶部范围筛选 + 状态筛选 + 搜索；表格首列为对象名称与 ID；**状态列统一用同一套标识**（内容状态、事实状态、同步状态）；行内显示待处理数量；批量操作栏。
